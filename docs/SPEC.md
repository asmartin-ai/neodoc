# Neodoc 1.0 — Format Specification

A Neodoc file is **one plaintext HTML5 document**. It renders in any browser with
zero JavaScript and zero network access. It is edited WYSIWYG with markdown-native
input, addressed from the command line by CSS selector, and converted to markdown
or docx.

The format is defined by the **canonical serialization** (§4). Two byte-identical
files have the same meaning; `neodoc fmt` is the canonicalizer and is idempotent.

- File naming convention: **`*.nd.html`** (`report.nd.html`). `*.ndoc.html` and
  `*.ndoc` are accepted when reading and when deriving names, but `.html` stays the
  **last** extension on purpose: browsers and static hosts pick the media type from
  the last extension, so a document opens and renders everywhere with no server, no
  MIME configuration and no JavaScript. The format's identity is the
  `data-neodoc` marker plus the `.nd.` infix, not the media type.
- Media type: `text/html; charset=utf-8`.
- Encoding: UTF-8, LF line endings, exactly one trailing newline, no tabs, no
  trailing whitespace.
- Version marker: `<html data-neodoc="1">` — REQUIRED.

---

## 1. Design decisions (and why)

| Decision | Reason |
|---|---|
| Canonical storage is **HTML**, not markdown | Comments, annotations, images, tracked changes, figures and tables need a real tree + attributes. HTML is also the only format that renders natively everywhere without a renderer. Markdown is the *input/output language*, not the store. |
| **Zero scripts** in a document (`<script>` is a lint error) | A shared document must be data, never code. Removes the whole class of "docx macro virus" and makes every tool that touches the file safe. |
| **One element per line**, 2-space indent | Line-oriented git diffs become semantic: moving a paragraph is one line moved, editing a word is a word-level diff inside a stable line. No reflow noise because lines are never hard-wrapped. |
| Closed element/attribute vocabulary | Keeps the file boring, lintable, convertible, and stable across editor versions. Browsers' own HTML serialization is *never* written to disk. |
| Enforced canonical `<style>` block in the head | The document renders identically as a static file with no CSS request. `fmt` restores it, so drift is self-healing. |
| Comments are `<mark>` + `<aside>`, changes are `<ins>`/`<del>` | These are standard HTML elements with standard semantics and standard docx/OOXML equivalents (`w:comment`, `w:ins`, `w:del`). No new inline brace syntax. |
| No `class`, no `style` attributes | `class` soup is what makes Word HTML unmaintainable. Attribute selectors (`[data-c]`) cover the same need. |
| Addressable by CSS selector, ids optional | Selectors are the boring standard; `fmt` never invents ids, so hand-written files stay clean. `neodoc get --json` prints a round-trippable selector for every block. |

## 2. Document skeleton

```html
<!doctype html>
<html data-neodoc="1" lang="en">
  <head>
    <meta charset="utf-8">
    <title>Quarterly report</title>
    <meta content="Ken" name="author">
    <meta content="2026-10-16" name="date">
    <meta content="neodoc 1.0.0" name="generator">
<style>
/* canonical stylesheet — see §6; regenerated byte-exactly by `neodoc fmt` */
</style>
  </head>
  <body>
    <h1 id="h-intro">Introduction</h1>
    <p>Plain text, <strong>bold</strong>, and a <mark data-c="c1">contested claim</mark>.</p>
    <aside data-state="open" data-thread="c1">
      <p data-at="2026-10-16T09:12:00Z" data-author="ada">Source?</p>
    </aside>
  </body>
</html>
```

Head order is fixed: `meta[charset]`, `title`, `meta[name]` sorted by `name`
(`generator` always **last**), `style`. Body content is a sequence of blocks (§3).
The `<style>` block is the one element whose content is emitted at column 0.

## 3. Vocabulary (closed set)

**Blocks**
`h1`–`h6`, `p`, `blockquote`, `pre`, `ul`, `ol`, `li`, `table`, `thead`, `tbody`,
`tr`, `th`, `td`, `figure`, `figcaption`, `hr`, `section`, `aside`, `img`.

**Inline**
`strong`, `em`, `code`, `s`, `u`, `mark`, `sub`, `sup`, `ins`, `del`, `a`, `img`,
`br`, plus text and HTML comments (`<!-- … -->`, one line, no `--` inside).

**Forbidden** (lint error): `script`, `style` outside `head`, `div`, `span`,
`iframe`, `object`, `embed`, `form`, `input`, `button`, `video`, `audio`, `svg`,
`link`, `base`, `meta` outside `head`, `html`/`head`/`body` outside their position.

**Allowed attributes** — anything not listed and not starting with `data-` is a
lint error.

| Scope | Attributes |
|---|---|
| all | `id`, `title`, `lang`, `dir`, `data-*` |
| `a` | `href`, `target` (`_blank` only, implies `rel="noopener"` added by `fmt`) |
| `img` | `src` (REQUIRED), `alt` (REQUIRED), `width`, `height` |
| `ol` | `start`, `reversed` |
| `td`, `th` | `colspan`, `rowspan`, `scope`, `data-align` (`left\|center\|right`) |
| `li` | `data-checked` (`true\|false`) — task list item |
| `pre` | `data-lang` |
| `section` | `data-title` (optional; heading text stays authoritative) |
| `mark` | `data-c` (comment id) |
| `aside` | `data-thread` (comment id), `data-state` (`open\|resolved`), `data-note` (`info\|warn\|danger\|tip`) |
| thread/reply paragraphs | `data-author`, `data-at` |
| `ins`, `del` | `data-author`, `data-at` |
| `meta` | `name`, `content` |

`data-at` is an ISO-8601 UTC timestamp (`2026-10-16T09:12:00Z`).
`meta[name=date]` is `YYYY-MM-DD`.

**Nesting rules**: `section` contains blocks, and may contain `section`.
`li` contains inline content or blocks. `blockquote` contains blocks.
`figure` contains exactly one `img` plus optional `figcaption`. `body` contains
blocks. No block inside an inline context.

## 4. Canonical serialization (normative)

Nesting is represented to a depth of 512 elements. A start tag deeper than that is
dropped and reported by `parse` (a `lint` finding; `fmt` warns on stderr and writes the
flattened tree), so a pathological file is reported rather than crashing the tools. The
content of a dropped element stays in its parent.

1. **Line discipline.** Every element starts on its own line. Children are
   indented **2 spaces** per depth level relative to `<html>`. No blank lines.
   No line is hard-wrapped.
   - A node whose children contain any [block-level element](#3-vocabulary-closed-set)
     (or an HTML comment) puts each child on its own indented line; otherwise the
     whole node is emitted on a single line with its inline content. This is one
     rule, not a list of exceptions: `<p>a <em>b</em></p>` is one line,
     `<tr><td>a</td><td>b</td></tr>` is three lines, `<ul><li>a</li>…` is
     multi-line, `<td>a</td>` is one line.
2. **Attribute order** is ascending byte order by attribute name. All ordering and
   comparison in this specification is by UTF-16 code unit, never by locale: the
   canonical bytes of a document MUST NOT depend on the platform, locale, ICU
   version or time zone (CI enforces this on Linux, macOS and Windows). Attributes are
   double-quoted, `=`, no spaces: `<img alt="x" src="y">`. Void elements use no
   self-closing slash: `<br>`, `<hr>`, `<img …>`, `<meta …>`.
3. **Escaping.** Text nodes escape exactly `& < >`. Attribute values escape
   exactly `& < "`. No other character references are emitted; non-ASCII is
   literal UTF-8. `fmt` decodes character references into their characters:
   numeric references (`&#8212;`, `&#x2014;`), and the named references of the
   WHATWG list (`src/entities-data.js`). Decoding is not optional — a valid
   reference that survives as text gets escaped and is then shown to a reader as
   its own spelling (`Jos&eacute;` would read `Jos&eacute;`). Therefore: a name
   outside the WHATWG list (`&nbsp2;`), a name HTML5 only accepts with its
   semicolon (`&hellip`), and an out-of-range or surrogate numeric reference all
   stay literal text, and an invalid numeric reference becomes U+FFFD, which is
   what a browser shows for it. Names are case-sensitive.
4. **Whitespace model.**
   - Runs of whitespace (space, tab, LF, CR, FF) collapse to one space. No other
     character is whitespace here: U+00A0 and other spaces keep their meaning.
   - Leading whitespace at the start of a block's content and trailing
     whitespace at the end of a block's content is removed.
   - Interior single spaces are preserved: `<p>Hello <strong>x</strong>!</p>`.
     A whitespace-only text node between two inline elements becomes one space.
   - Empty text nodes are dropped.
   - `pre` content is verbatim except: each continuation line (line 2 onward) is
     indented to the element's own indentation and parsing removes exactly the
     common leading indentation of those lines, so `pre` content is normalized to
     its minimum indentation. HTML escaping still applies inside `pre`, and a
     trailing newline before `</pre>` is not part of the content. Whitespace-only
     lines inside `pre` are emitted with their spaces, which is the one place
     trailing whitespace is allowed.
5. **Ids.** Optional. `fmt` never creates, changes, or removes them. Within a
   document ids are unique (lint error if not).
6. **`fmt` normalizes but does not restructure**: element names are lowercased,
   `<b>`→`<strong>`, `<i>`→`<em>`, `<strike>`→`<s>`, `align` on `td`/`th`
   → `data-align`, presentational attributes (`border`, `cellpadding`, `bgcolor`,
   `color`, `face`, `valign`, `style`, `class`, `role`) and event handlers
   (`on*` — code, not content) are dropped with a warning, a stray `=` between
   attributes is skipped,
   nested identical inline elements (`<em><em>x</em></em>`) are merged, and empty
   inline elements are removed. Unknown elements and unknown attributes are
   **kept** (never deleted) and reported by `lint`; `script` content is passed
   through untouched.
7. **Idempotence.** `fmt(fmt(x)) == fmt(x)` for all inputs. This is a test.

## 5. Comments, annotations, tracked changes

Comment anchor (inline, wraps the commented text; the text stays in place):
`<mark data-c="c1">text</mark>`

Thread (block, placed immediately after the block it anchors to, else at the end
of the containing `section`, else end of `body`):

```html
<aside data-thread="c1" data-state="open">
<p data-author="ada" data-at="2026-10-16T09:12:00Z">Is this still true?</p>
<p data-author="ken" data-at="2026-10-16T10:00:00Z">Yes — see the appendix.</p>
</aside>
```

- Comment ids: `[a-z0-9]{1,32}`, unique. `neodoc` generates `c1`, `c2`, ….
- Replies are further `<p>` children. The **first** `<p>` carries the original
  comment text. An `<aside data-thread>` with no matching `<mark data-c>` is a
  **document-level annotation** — legal, and shown in the margin.
- A `<mark data-c>` with no matching thread is a lint error.
- `data-state="resolved"` hides the thread in rendering and highlights nothing.
  Resolved threads are kept in the source (history belongs to git).
- Rendering: `mark[data-c]` gets a subtle highlight; threads render as a bordered
  block; `del` is red strikethrough, `ins` is green underline.

Tracked changes use native HTML: `<ins data-author="ada" data-at="…">added</ins>`
and `<del …>removed</del>`. `neodoc accept` / `neodoc reject` folds them.

## 6. Canonical stylesheet

The `<style>` block in the head is the exact byte output of `neodoc css`
(source of truth: `src/theme.js`). `fmt` replaces any existing head `<style>`
with it; `neodoc fmt --style=none` removes it (documents then use browser
defaults), and `neodoc fmt` adds it to a document that has none only when
`--style=inline` is passed explicitly. The stylesheet is presentation only and
MUST NOT affect semantics: it must not use `display:none` on any content element
— resolved comment threads (`aside[data-thread][data-state="resolved"]`) are the
single exception — and must not reorder content.

It provides: system font stack, readable measure, table borders, aligned cells
via `[data-align]`, code blocks, figure centering, dark-mode via
`prefers-color-scheme`, print rules (`@page` margins, `break-inside: avoid` on
figures/tables/`pre`, `orphans`/`widows`, heading `break-after: avoid`),
comment/ins/del styling, `[data-checked]` task markers, and hiding of resolved
comment threads.

## 7. Addressing and the CLI

Selectors are the addressing language, over the parsed tree, rooted at the
`<html>` element (so `body > p` works, and `head > title` is reachable).
Supported: `tag`, `*`, `#id`, `[attr]`, `[attr=val]`, `[attr^=val]`,
`[attr$=val]`, `[attr*=val]`, descendant (space), child (`>`), `:first-child`,
`:last-child`, `:nth-child(n)`, `:nth-of-type(n)`, `:not(simple)`. Comma = union.
Class selectors are unsupported because the vocabulary has no classes.

Commands (see `docs/CLI.md` for the full reference):

```
neodoc fmt [-w] [--check] [--style=inline|none] FILE...
neodoc lint [--json] [--fix] FILE...
neodoc get FILE SELECTOR [--json] [--text]
neodoc set FILE SELECTOR (--md S | --html S | --file F | --stdin)
neodoc add FILE (--before SEL | --after SEL | --into SEL) (--md S | --html S | --file F | --stdin)
neodoc rm FILE SELECTOR
neodoc new [FILE] [--title T] [--stdin]
neodoc id FILE --for SELECTOR --as NAME
neodoc note add FILE SELECTOR --say T [--on QUOTE] [--by AUTHOR] [--at TS]
neodoc note ls FILE [--json] [--open | --done]
neodoc note reply FILE ID --say T
neodoc note done|undo|rm FILE ID
neodoc accept FILE [SELECTOR]
neodoc reject FILE [SELECTOR]
neodoc import [FILE.md] [-o OUT]
neodoc md FILE [-o OUT] [--comments html|critic|drop]
neodoc docx FILE [-o OUT]
neodoc serve FILE [--port N] [--open]
neodoc bench FILE [--rounds N]
neodoc css
```

- Mutating commands write in place by default; `-o -` writes to stdout.
- `get --json` returns `{path, tag, id, attrs, text, html}` per match and is the
  agent interface. Selectors that match only nodes outside `<body>` are rejected
  by mutating commands.
- Exit codes: `0` success, `1` lint/`--check` violations or no match, `2` usage error.
- Writes are atomic (temp + rename) and leave the file canonical: opening a
  document canonicalizes it first, so a write to an already-canonical file changes
  only the lines the command touched.

## 8. Conversion

- **→ markdown**: GFM-compatible subset. Headings, paragraphs, lists (task lists
  via `[x]`), blockquotes, fenced code with `data-lang`, GFM tables with
  alignment, figures→`![alt](src)` + italic caption paragraph, `hr`, links,
  images, `**`/`*`/`` ` ``/`~~`/`==`/`<sub>`/`<sup>`. `data-checked` → `[x]`.
  Anything the subset cannot carry *exactly* — an attribute markdown has no slot for,
  an `img` without `alt`, a caption that is itself emphasised, a fence info string
  that is not a single word — is emitted as canonical raw HTML, which GFM passes
  through and `import` reads back unchanged.
  Comments: `--comments=html` (default) emits `<mark data-c>`/`<aside data-thread>`
  verbatim so nothing is lost; `critic` emits `{==text==}{>>author: text<<}`;
  `drop` strips them. Inline `id`s are preserved as `<a id>` anchors when present.
- **→ docx**: `w:p`/`w:tbl` with a styles part the writer defines itself (no
  reference document is read, and there is no flag to point it at one). Images become `word/media/*`. Comment anchors become real Word
  comments (`word/comments.xml`, `commentRangeStart/End`). `ins`/`del` become real
  tracked changes (`w:ins`/`w:del`) with author and date. `data-lang` becomes a
  "Neodoc Code" paragraph style. No loss of text content.
- **← markdown**: `import` accepts the same subset; unsupported constructs are
  reported as warnings, never silently dropped.

## 9. Performance requirements

- Rendering: the browser renders the static document; Neodoc ships no renderer.
- Editing: the editor mutates the live DOM; no re-parse and no re-render per
  keystroke (typing is O(1)).
- CLI: parse + format is a single linear pass. Reference budget on a 2,000-block
  (≈250 KB) document: `get`/`set`/`fmt` under 150 ms, `to docx` under 500 ms on a
  modern laptop. `neodoc bench` measures this and CI asserts the budget.

## 10. Conformance

A conforming implementation MUST: `fmt` a canonical file to byte-identical output;
report forbidden elements as lint errors; keep every unknown construct in the file
while reporting it; and round-trip a document through markdown without losing text.

`neodoc test fixtures/` is the runnable check:

1. every `fixtures/*.nd.html` is already canonical (`fmt` returns the same bytes)
   and lints with zero findings;
2. every `fixtures/noncanonical/*.html` canonicalizes byte-exactly to
   `fixtures/<name>.nd.html`, which exercises tag case, attribute order, whitespace,
   implied end tags and character references.

Ports run the same protocol (docs/PORTING.md).
